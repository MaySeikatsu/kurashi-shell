# Card M1.5-frontend — Quickshell frontend skeleton (`frontend/`)

**Goal.** Turn the winning bake-off probe (`archive/bakeoff-probes/quickshell`, K3) into the real frontend's
skeleton: a thin view that subscribes, renders, sends intents — no business logic, no polling,
no `Process` (rules 1, 5).

**Owned paths:** `frontend/` (new), `i18n/en/frontend.toml`, `i18n/ja/frontend.toml` (new; one
file per locale and domain so cards never conflict). Common rules: `docs/tasks/README.md`.

**Read:** `archive/bakeoff-probes/quickshell/*` (start from it), `archive/bakeoff-probes/quickshell/REPORT.md`, `docs/PROTOCOL.md`
§1–4 + §8, `docs/ARCHITECTURE.md` §4, `docs/DESIGN-SYSTEM.md` §7–9, `tools/bakeoff/CANDIDATES.md`
quickshell section (gotchas).

**Build (QML only; run with `qs -p frontend`):**
1. Structure: `frontend/shell.qml`; `core/` — `Store` (IPC client: hello/welcome, subscriptions,
   merge-patch, revision-gap → `resync`, backoff reconnect 250 ms → 4 s, keeps last state,
   exposes `connected`), `Theme` (token accessor with fallbacks, the only place reading
   `theme.tokens`), `I18n` (`tr(key)`; until the daemon serves strings, return the key and add a
   CONTRACT-CHANGE row requesting an `i18n` document); `components/` — Button, IconButton,
   Slider (optimistic intents as in the probe), Chip, **ProvenanceChip** (renders a `Provenanced`
   `{value, source, forced_by?, reason?}`: source badge, tooltip with reason, "inert" style when
   forced), Island (face morph, interruptible); `surfaces/` — `Bar` (per output, hotplug) and
   `Stage` (ARCHITECTURE §4: one overlay layer surface per output that holds popups/OSD/island
   expansion, **mapped only while something is visible**, input region = visible content,
   reveal gated on its first presented frame). Move the probe popup into the Stage.
2. **Reconnect veil:** when the daemon connection drops, keep the last state, dim the bar
   content subtly (token-driven) and show a small disconnected glyph; clear on resync.
3. All strings through `I18n.tr` with keys in `i18n/{en,ja}/frontend.toml`.
4. Ma: zero timers/animations at idle; every animation has a visibility gate.
5. A `frontend/README.md`: how to run against the mock in the sandbox, the folder layout and the
   component conventions (token-only styling, no renderer branches on theme/profile names).

**Not yours:** anything in Rust, the mock, the protocol. Data comes from `kurashi-mock` (probe
subset). The ProvenanceChip can be demoed with a static sample until the lead serves `cfg.*`.

**Acceptance (one command, from repo root inside `nix develop`):**
`python3 tools/bench/measure.py --name frontend --warmup 10 --idle 30 -- qs -p frontend` →
`pass_a.error` absent, `idle_commits_per_s` ≤ 0.05, `pass_b.popup_latency_ms_median` and
`morph_commits` non-null, survived hotplug. Plus sandbox screenshots (bar idle, stage popup open,
disconnected veil after stopping the mock, 2 outputs) checked by you — keep them out of git
except `frontend/shots/*.png` (≤ 4 files). Build the mock first:
`cargo build -p kurashi-mock -p kurashi` (shared target dir; then copy or symlink the two binaries
into `target/release/` of your worktree, which `measure.py` expects).
