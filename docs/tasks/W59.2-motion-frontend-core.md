## Build
- Until W59.1 lands, the `motion.curve.*`/`motion.form.*`/`motion.accent.*` tokens are absent: the Theme readers derive
  them from today's tokens (`motion.timed.*`, `motion.spring.*`, `motion.kind`, `motion.style`) so everything works and
  stays pixel-identical standalone; with W59.1's tokens present they read those. Note `settings/core/Theme.qml` is a
  symlink to `frontend/core/Theme.qml`.
- `curves.js`: cubic segments (Newton 4 steps + bisection fallback, cached per curve), analytic spring with initial
  velocity, steps, `spring_q` = the K42 16-ms integrator **copied from MorphSprings** (bit-exact), retarget for cubic:
  the new curve's first handle scaled so its start slope equals the current velocity (clamped), springs keep v natively.
- `Driver.qml`: as the contract; one `FrameAnimation`, `running` only while moving; `KURASHI_MOTION_SCRUB=<p>` (read once
  via the environment, `Quickshell.env`) holds every Driver at p and logs `motion: scrub <p>`; `track/release` for the
  Settings scrubber (W59.6) and later gestures.
- `Glide` and MorphSprings' timed axes run on `curves.js` with the token curves; springs (calm/lively) through `spring_q`.
- `FormHost`: latches the form per transition; shape family → exposes `form` for the morph (W59.3 wires surfaces);
  sheet family → Loader for `forms/<Form>.qml` (none exist yet; a missing component logs once and falls back to `fade`).
- `Accents`: jelly = area-preserving Scale (sx = 1 + a·s(t), sy = 1/sx) driven by a short spring after landing;
  squash as MorphSprings' today. `Stagger`: attached `progress` for child i from the host's progress (no timers).
