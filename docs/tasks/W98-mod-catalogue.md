# W98 — The mod catalogue: an index repository, with Nix beside it (session 34, K155; I570; brief first)

After W93 (host programs) and W94 (the editor). A UX brief `docs/ux/mod-catalogue.md` first (VS Code's Marketplace and
Open VSX, Raycast's store, HACS, GNOME's extensions site, KDE's Get Hot New Stuff, nixpkgs' plugin sets, Zed's
extensions; states: offline, an entry that does not fit this version, a hash that does not match, an update, a mod with a
host program; keyboard, a11y; what the user reads before installing: provides, uses, capabilities, the program it runs).

## Shape (to settle in the brief, then with the user)
- **The index:** a git repository, one file per mod (`mods/<id>.toml`: id, name, description, icon, versions with the
  shell's range, the source — a git URL and revision or an archive — and its hash, the manifest's summary generated by
  `kurashi mod check --summary`). A pull request is the review; CI runs `kurashi mod check` on the source.
- **The CLI and the page:** `kurashi mod add <id>[@version]`, `update`, `remove`, `list --available`; Settings › Mods
  gets "Browse" (the index, fetched on demand — never polled), an entry's page, Install, Update. Installs go to the user's
  mods folder with a `.source` file (where it came from, its hash); a hash that does not match is refused.
- **Nix:** `programs.kurashi.mods.<id> = { rev; hash; }` (or an attribute set built from the index) puts the same sources
  into the store and the daemon's mod roots, read-only; the Mods page shows such a mod as managed (provenance `nix`,
  Install and Remove inert with the reason).
- **First-party mods** stay in the tree for now; whether some move out is asked again when the index exists.
